# 02-separacion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Partir el monolito en tres servicios FastAPI con base propia, comunicados por HTTP, detrás de un proxy Nginx que sirve la UI.

**Architecture:** Cada servicio en `services/<nombre>/` es una copia autónoma de la estructura del monolito (`app/{main,config,db,shared,modules}`) con solo sus módulos, su cadena Alembic y sus pruebas. Lo que antes era `import` de otro servicio pasa a un cliente `httpx` en `app/clients/` que conserva nombres y tipos de retorno de la función original (sin `session`). `web/` construye el SPA y reparte `/api/...` por prefijo.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2 async, Alembic, httpx, PostgreSQL 16, Nginx alpine, Docker Compose, Vue 3.

**Spec:** `docs/superpowers/specs/2026-11-03-02-separacion-design.md`

## Global Constraints

- Sin dependencias nuevas; `httpx>=0.27` pasa de `dev` a `dependencies` en los servicios que llaman a otros.
- Ningún archivo de un servicio importa código de otro servicio; sin FK ni bases compartidas.
- Variables `FLDSMDFR_*`; URLs remotas: `FLDSMDFR_CATALOG_URL=http://catalog-streaming:8000`, `FLDSMDFR_USERS_URL=http://users-playlists:8000`.
- Bases: `users_playlists`, `catalog`, `playback` (y `<base>_test`) en un solo `postgres:16-alpine`.
- Endpoints internos bajo `/internal`, nunca expuestos por el proxy.
- Falla remota (red o 5xx) → `503` con `code="service_unavailable"`; 404 remoto → el mismo `NotFound` y código que hoy (`song_not_found`).
- Rutas públicas idénticas a `01-monolito`; la UI no cambia.
- Puerto público único `8000` (`web`).
- Textos y documentación en español.

## Review Focus

1. Streaming con `Range` a través de Nginx: `206`, `Content-Range` y sin buffering → prueba manual en Task 5 con `curl -r 0-1023`.
2. `/api/me/history` debe ir a `playback-metrics` aunque `/api/me/` vaya a `users-playlists` → `curl` en Task 5.
3. Subida de 20 MB por el proxy (`client_max_body_size`) → prueba manual en Task 5.
4. Catálogo caído: el detalle de casete y registrar reproducción responden `503` uniforme, no 500 → pruebas de cliente en Tasks 3 y 4.
5. `/internal/...` desde fuera → `404` en el proxy → `curl` en Task 5.
