# Rama `06-poliglota` — plan de implementación

> **Para agentes:** SUB-HABILIDAD REQUERIDA: usa superpowers:subagent-driven-development (recomendada) o superpowers:executing-plans para implementar este plan tarea por tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** que las lecturas frecuentes del catálogo y de las gráficas salgan de una caché en Redis, aparte del Redis durable, y que si la caché cae todo responda igual desde PostgreSQL.

**Arquitectura:** un servicio `redis-cache` (LRU, sin persistencia) y un módulo `meloxo_common.cache` con lectura tolerante a fallos. El catálogo invalida por versión (un contador dentro de la clave, que sube en cada escritura); las gráficas, por TTL corto. El estado de cuenta gana un segundo nivel compartido en la misma caché.

**Tecnologías:** Python 3.12, FastAPI, SQLAlchemy async, `redis.asyncio`, `fakeredis` en pruebas, pytest, Docker Compose.

**Diseño:** [`docs/specs/2026-11-14-06-poliglota-design.md`](../specs/2026-11-14-06-poliglota-design.md)

## Restricciones globales

- MongoDB queda fuera; PostgreSQL sigue siendo la única fuente de verdad (diseño §3, §4).
- `redis-cache`: `--maxmemory 64mb --maxmemory-policy allkeys-lru --save "" --appendonly no`. El servicio `redis` actual no se modifica (diseño §2.1, §5).
- Variable `CACHE_REDIS_URL`, independiente de `REDIS_URL`. Vacía, no hay caché y todo funciona igual (diseño §5).
- Timeouts: lectura 0,2 s, escritura 0,3 s; tras un fallo se salta la caché 5 s (diseño §5).
- TTL: catálogo y géneros 300 s; agregados 15 s; estado de cuenta 30 s (diseño §5).
- Claves: `cache:ver:catalog`, `cache:catalog:{ver}:...`, `cache:auth:{user_id}`. Las lecturas personales incluyen `scope`, el usuario y todos los parámetros (diseño §5).
- No se cachean contadores de reproducciones, escrituras, tickets de streaming ni rutas de administración (diseño §3).
- Textos de log, comentarios, docstrings y documentación en español, como el resto del repositorio.
- Los commits de MELOXO **no** llevan `Co-Authored-By`.
- Pruebas: desde `services/<servicio>`, `../../.venv/bin/python -m pytest -q`. Necesitan el Postgres de `docker compose` en el puerto 5433.

## Foco de revisión

Entradas o fallas que el diseño implica y que ninguna tarea cubre por sí sola; cada una tiene su prueba en la tarea que se indica.

1. `redis-cache` caído o lento: la respuesta es la misma y no se paga un timeout por petición (Tareas 1 y 3).
2. Una pista oculta o borrada deja de salir en la siguiente lectura, no cuando vence el TTL (Tarea 3).
3. Un error 404 (pista o artista inexistente) no se guarda en la caché (Tarea 3).
4. Dos usuarios con `scope=me`, o dos zonas horarias, no comparten entrada (Tarea 4).
5. Un resultado de `top` con etiquetas «No disponible» (catálogo caído) no se guarda (Tarea 4).
6. Una sesión revocada se rechaza aunque el estado de cuenta esté en la caché compartida (Tarea 5).

**Interfaces:**
- Produces, en `meloxo_common.cache`:
  - `get_cache() -> Redis | None` (cliente propio, `decode_responses=True`, mismos timeouts de conexión que `redis_client`; `None` sin URL)
  - `override_cache(client: Redis | None) -> None`, para pruebas
  - `async def cached(namespace: str, params: dict, ttl: int, loader: Callable[[], Awaitable[Any]], *, versioned: bool = False, should_store: Callable[[Any], bool] = lambda _: True) -> Any`. Devuelve el JSON guardado o llama a `loader`, guarda `jsonable_encoder(resultado)` si `should_store` lo permite y lo devuelve. Si `loader` lanza, la excepción sube y no se guarda nada. Con `versioned=True` lee `cache:ver:{namespace}` **una sola vez al inicio** y lo usa en la clave.
  - `async def bump(namespace: str) -> None`: `INCR cache:ver:{namespace}`; nunca lanza.
  - `async def get_json(key: str) -> Any | None` y `async def set_json(key: str, value: Any, ttl: int) -> None`: nunca lanzan.
  - Constantes `READ_TIMEOUT_SECONDS = 0.2`, `WRITE_TIMEOUT_SECONDS = 0.3`, `SKIP_AFTER_FAILURE_SECONDS = 5.0` y `_skip_until` a nivel de módulo, como en `revocation.py`.
  - La clave sale de `namespace`, la versión y un SHA-256 del JSON de `params` con llaves ordenadas.
